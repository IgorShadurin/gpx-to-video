# Working on gpx-to-video

This is a public Rust CLI and local layer viewer. Keep changes reproducible using synthetic fixtures. Never commit a user's rides, videos, paths, coordinates, identity, tokens, signing material, private instructions, browser state, or machine logs. Generic engineering guidance belongs here. `examples/synthetic-ride.*` is generated by `scripts/make-fixtures.py` and is not a personal recording.

## Modules

- `telemetry.rs`: GPX/CSV decoding, timestamps, validity, segments, distance, indexed sampling.
- `video.rs`: ffprobe, per-clip timing, directory planning, FFmpeg, output validation and reports.
- `maps.rs`: OSM downloads, disk/LRU caches, projection and nearby road/place labels.
- `render.rs`: shared raster/text primitives and canvas bounds.
- `render/gauge.rs`, `render/map.rs`, `render/stats.rs`: independent widgets. Change one without modifying the other widgets or telemetry.
- `config.rs`: typed configuration and validation. Unknown options fail; defaults and the generated example must agree.
- `viewer.rs`, `assets/viewer.html`: loopback browser configurator. Preview and export use the real renderer.
- `main.rs`: CLI orchestration only.

## Iterate on a layer

1. Build with `cargo build --release`.
2. Run `target/release/gpx-to-video init --output tmp-theme.toml` if a full configuration is needed. Do not overwrite an existing user's theme.
3. Run `target/release/gpx-to-video view --config tmp-theme.toml` and open the printed loopback address. Without a route it uses explicitly labeled dummy values and a synthetic map. The viewer updates a single PNG, not a video.
4. Change widget x/y/size, visibility, palette or language. Save the configuration through **Save theme.toml**. For frame comparisons use `preview --config theme.toml --output output/preview.png`; add `--language en` for English.
5. For real data use `preview --route track.gpx --seconds 30`. Seconds are relative to the track's start. Video matching belongs to `render --video …`, where UTC capture time and explicit clock corrections select the samples.
6. Inspect the actual PNG at native 4K and at 1080p. Check 0, normal and maximum speed; missing GPS; long Cyrillic/English names; units; readable shadows; alpha edges; attribution; and all widget bounds. Verify text is rendered by a font that contains the glyph, not a replacement box.
7. For a video-path change run `python3 scripts/smoke-test.py` after the release build. Confirm alpha with `alphaextract` (force the `libvpx-vp9` decoder for WebM). A black viewer background does not prove transparency.

The default theme is **bicycle**. Keep the gauge's green-to-yellow-to-red arc, white readable speed and needle, and transparent surroundings. The reference look uses simple geometric primitives, drawn at output resolution. Use ImageGen for genuinely pictorial new assets; preserve generated alpha and record a generic prompt/source in `assets/README.md`. Do not put a grass photograph inside the gauge. The demo background is separate from the overlay. Do not copy game icons or UI screenshots into distributed assets.

All palette and widget positioning choices should flow through typed configuration. Keep sizes relative to the canvas; do not hard-code a 1080p raster and upscale it. Changing map colors must not invalidate or redownload the raw OSM geometry. Keep attribution legible. A demo map must be labeled as synthetic.

Public README showcase images use English labels and actual OSM geometry, never the synthetic grid map. Generate them with `preview --language en --map-source osm` using cached public-area data and synthetic telemetry. Keep the fictional background/demo readings explicitly identified and OSM attribution visible. This presentation rule does not change the application's default language.

Coordinates are hidden by default (`show_coordinates = false`). Keep the optional control available and ensure documentation previews follow the default.

## Correctness and performance rules

- Match telemetry by UTC timestamp, never row number or file modification date. Require an explicit offset on manually supplied dates. Keep clock corrections in per-job configuration, not source code.
- Preserve segment boundaries and GPS gaps. Invalid speed is not zero. Mark a missing value with a dash. Interpolation is an estimate between nearby measurements, not new recorded GPS data.
- Do not smooth through stops, outages, or camera restarts. Use actual measured speed before estimating from coordinates. Round only for display; retain source precision for sampling.
- Keep track lookup O(log n), bounded map caches, cached glyphs/static graphics, and a single streamed frame. Do not accumulate frames or traverse the whole ride for every video frame.
- Do not add a remote reverse-geocoding call per frame. Names come from cached vector geometry, with a distance threshold and explicit nearby-place wording.
- Preserve source dimensions, supported codec family, constant frame rate, bit depth and copied audio. Burn-in requires re-encoding; never describe it as a lossless stream copy. Retain timing/codec assertions in the smoke test.
- Reject unsupported color/timing cases with an actionable alternative. D-Log M/HDR should use a separate alpha layer until color-managed burn-in is implemented and tested.
- Validate and write to a partial output before promoting it. Do not overwrite source files. Keep an output directory outside an input directory. Do not run downloaded strings through a shell.
- Fetch only required OSM cells, cache by zoom, keep requests bounded/sequential, retain completed downloads on error, and respect offline mode. Do not bulk-download the public OSM raster tile service.
- Viewer: bind to loopback, check Host/Origin, limit request size, expose no shell execution or arbitrary filesystem-writing endpoint. Browser-selected backgrounds stay local.

## Before publishing

Run formatting, strict Clippy, and unit/integration tests. After media changes, run the synthetic media smoke test. Review actual before/after PNGs in Russian and English. Record measured results without claiming untested hardware, Action 6 files, Linux, Windows, long-duration memory stability or zero hitches.

Run `scripts/check-public-content.py` and inspect staged files. Only synthetic examples and generic documentation belong in git. Keep map cache and media outputs ignored. Use a public/noreply author email. Do not include a local absolute path in public docs, validation reports or workflow definitions. The repository's assets must carry applicable font/map/image attribution.
